# Known Issues & Operational Notes (`KNOWN_ISSUES.md`)

1. **`SCHED_FIFO` Real-Time Thread Priority Requires `CAP_SYS_NICE`**:
   - When running as an unprivileged desktop user without `CAP_SYS_NICE` or `/etc/security/limits.conf` `rtprio` permissions, `vach::AudioIo` logs a structured warning (`SCHED_FIFO priority 50 unavailable on vach_capture (CAP_SYS_NICE not granted); falling back to SCHED_OTHER`) and pins the capture and playback threads to CPU cores 4 and 5 under `SCHED_OTHER`. Even under `SCHED_OTHER`, 1-hour ring buffer stress testing and 20-turn continuous TTS playback achieve `0` overruns, `0` underruns, and `0` ALSA xruns.
2. **ThreadSanitizer (`release-tsan`) Suppressions for Uninstrumented External Shared Libraries**:
   - External C/C++ shared libraries loaded at runtime (`libcuda.so`, `libggml-*.so`, `libllama.so`, `libonnxruntime.so`, `libespeak-ng.so`, `libwhisper.so`, `libasound.so`, `libssh2.so`, and release builds of `libsutra.so` / `libyantra.so`) are compiled without `-fsanitize=thread`. `cmake/tsan.supp` suppresses false-positive TSan reports across these uninstrumented library boundaries while enforcing full TSan checking across all Sphinx translation units.
3. **AddressSanitizer (`release-asan`) and CUDA Unified Memory Shadow Gap**:
   - Initializing CUDA (`cuInit`) under AddressSanitizer requires `ASAN_OPTIONS=protect_shadow_gap=0:detect_leaks=0`, which is configured automatically on all `ctest` targets in `CMakeLists.txt`.
4. **`llama.cpp` MoE Expert Offloading (`n_cpu_moe`) via `tensor_buft_overrides`**:
   - The installed `llama.h` (`$HOME/.local/include/llama.h`) implements `--n-cpu-moe` via `llama_model_params::tensor_buft_overrides` (`const struct llama_model_tensor_buft_override *`) rather than a struct field named `n_cpu_moe` in `llama_model_params`. `sutra::LlamaCppClient` maps `LlamaCppConfig::n_cpu_moe` to regex overrides `blk\.{i}\.ffn_(up|down|gate|gate_up)_(ch|)exps` bound to `ggml_backend_cpu_buffer_type()`.
5. **Identity Leak on `Q4_K_M` Models (`RESOLVED`)**:
   - **Root Cause**: At `Q4_K_M` quantization without an explicit identity system prompt, `Qwen2.5-1.5B-Instruct` had insufficient post-training signal to override dominant `"I was created by Anthropic"` patterns in its training data when asked `"Who created you?"`.
   - **Fix**: Added `kSphinxIdentityPrompt` in `src/session.cpp` and prepended it as the first system content on both the `CHAT` (`Qwen2.5-1.5B-Instruct`) and `TASK` (`Qwen3-30B-A3B`) paths via `build_chat_system_prompt ()` and `build_task_system_prompt ()`. Verified 30/30 passes across 5 identity prompts × 3 runs on both paths.
6. **Desktop GPU VRAM Headroom Variance (`RESOLVED`)**:
   - **Root Cause**: Desktop GUI processes (`Xorg`, `gnome-shell`, `nautilus`, `firefox-esr`) consume ~747–805 MiB of baseline GPU VRAM, pushing startup VRAM from `7.17 GB` (in headless bench at `n_cpu_moe = 28`) to `7.46 GB` in live desktop sessions against the `7.50 GB` ceiling.
   - **Fix**: Increased `SphinxSessionConfig::big_model_n_cpu_moe` from `28` to `32` in `include/sphinx/session.hpp` (mapping to `40` of `48` MoE layers in host RAM and `8` MoE layers + all `48` GQA attention layers on GPU in `src/session.cpp`). Startup and steady-state peak VRAM dropped to **`6.89 GB`** (`<= 7.20 GB` target) while sustaining **`24.77 tok/s`** p50 `TASK` decode throughput.
7. **Tool Confabulation on `pwd` and `mkdir` Prompts (`RESOLVED`)**:
   - **Root Cause**: (1) `plan_node` in `src/session.cpp` previously lacked branches for `pwd`/working-directory queries and `mkdir`/directory-creation requests (falling through to `list_dir` or `write_file` on `notes.txt`), and `"pwd"` was missing from `kAllowedPrefixes` in `src/tools.cpp`; (2) `combined_tool_out` and `first_tool_error` in `src/session.cpp` were previously truncated at `28` / `32` bytes (`Command is not in Sphinx allowli`), cutting off the working directory path or disallowed command name before summarizing.
   - **Fix**: Added `"pwd"` to `kAllowedPrefixes` in `src/tools.cpp`, added explicit `pwd` and `mkdir` routing/planning in `src/router.cpp` and `src/session.cpp`, and expanded path/error forwarding to `64` bytes. Verified with `SPHINX_DEBUG_TOOLS=1` across all 3 reproducer prompts (`"run pwd"`, `"make a new directory called NewDir"`, `"what is the current directory address"`) with zero confabulation.
   - **Follow-up**: Added dedicated `make_directory(path)` tool so directory creation inside `SPHINX_SANDBOX` succeeds directly rather than hitting `run_command`'s allowlist rejection.
8. **Cross-Session Memory Cold-Start & Anisotropy Calibration (`RESOLVED`)**:
   - **Root Cause**: (1) Sessions previously started cold without persistent fact, correction, or episodic recall; (2) raw last-token embeddings from `Qwen3-Embedding-0.6B-Q8_0.gguf` exhibit a common-mode anisotropy floor (`cosine ~0.53` between unrelated short sentences); (3) loading `Qwen3-Embedding-0.6B-Q8_0.gguf` with `mparams.devices == nullptr` while `libggml-cuda.so` is initialized causes `llama.cpp` to attach a CUDA scheduler buffer even when `n_gpu_layers = 0`.
   - **Fix**: Implemented `sphinx::EmbeddingClient` (`mparams.devices` explicitly bound to `GGML_BACKEND_DEVICE_TYPE_CPU`, `n_gpu_layers = 0`, `LLAMA_SPLIT_MODE_NONE`, baseline anisotropy subtraction + L2-normalized content-word topic projection) and `sphinx::MemoryStore` (`yantra::WalEngine` + `yantra::HnswIndex` at `~/sphinx-workspace/.memory/`), with 30-day exponential episodic decay and `CORRECTION` supersession.
9. **Trust Fixes: Date Hallucination, Sandbox Dishonesty, Tool Output Truncation, & Meta-Question Routing (`RESOLVED`)**:
   - **BUG 1 — Date Hallucination (`RESOLVED`)**: Regenerated `"Current date and time: %Y-%m-%dT%H:%M:%S%z (%A)..."` on every turn in `build_chat_system_prompt ()` and `build_task_system_prompt ()` (`src/session.cpp`), with `sphinx::set_clock_override_for_testing` for deterministic cross-midnight testing.
   - **BUG 2 — Sandbox Dishonesty (`RESOLVED`)**: Updated `write_file`, `read_file`, `list_dir`, `make_directory`, and `validate_allowed_command` in `src/tools.cpp` to return refusals naming both the requested path/command and the allowed sandbox root; updated `plan_node` in `src/session.cpp` to extract the user's exact target path and content rather than substituting `notes.txt` with 33 fabricated bytes, and instructed the summarizer to quote tool refusals verbatim (`TEST-A`..`TEST-D` in `tests/test_integration.cpp`).
   - **BUG 3 — Aggressive 64-Byte Tool Truncation (`RESOLVED`)**: Replaced the global 26/64-byte truncation in `src/session.cpp` with per-tool `sphinx::TruncationPolicy` (`kLimits`) and `sphinx::truncate_tool_output` (`"<head bytes>\n...[truncated N bytes]...\n<tail bytes>"`).
   - **BUG 4 — Router Meta-Question Misclassification (`RESOLVED`)**: Added `kMetaQuestionKeywords` in `src/router.cpp` forcing `Route::CHAT` on capability/tool meta-questions, and extended `kSphinxIdentityPrompt` in `src/session.cpp` with the 9-tool list and `run_command` allowlist.
10. **Deferred Items (Out of Scope for Trust Fixes Patch)**:
   - **BUG 5 — Sentence-Splitter Short-Turn Leak (`DEFERRED`)**: Single-word acknowledgments such as `"Interesting"` can occasionally produce a truncated trailing fragment (`"Can y"`) at the sentence-splitter boundary.
   - **BUG 6 — Implicit Fact Extraction Triggers (`DEFERRED`)**: Implicit self-introductions without an explicit trigger keyword (e.g., `"My name is Kival"` without `"Remember that..."`) are not yet stored as `SEMANTIC` memories by `extract_explicit_semantic_facts`.
11. **System Observation Operational Notes (`Phases 1–4`)**:
   - **Session Profile Staleness (`O1`)**: The system profile (`gather_session_profile`) is captured once at `SphinxSession::create` and is not regenerated mid-session. If packages are installed, disks are mounted, or services change state during an active session, `run_readonly` should be used to query live state.
   - **Unprivileged `journalctl` / `dmesg` / `/var/log` Access**: `run_readonly` and `read_file_system` execute with the user's unprivileged UID/GID (`sudo` and `pkexec` are strictly forbidden). On systems where `kernel.dmesg_restrict = 1` or the user is not in the `adm`/`systemd-journal` group, kernel logs or root-only files in `/var/log` may return permission warnings or partial user-visible entries.
   - **Phase 4 Structured Tools Deferred**: Higher-level JSON diagnostic tools (`get_system_info`, `list_processes`, `service_status`, `recent_logs`, `network_info`, `gpu_info`) are specified in `SPEC_STRUCTURED_TOOLS.md` and deferred until Phases 1–3 have been exercised in live usage for at least one week.
12. **Comprehension Fixes: Hard Refusal, Fibonacci Gate, Read-Intent Expansion, & CHAT Grounding (`RESOLVED`)**:
   - **BUG A — Default Tool Fallback to `list_dir` (`RESOLVED`)**: Removed the unconditional `else` fallback to `list_dir` in `SphinxSession::process_text_turn` (`src/session.cpp`) and introduced `enum class PlanOutcome { PlanReady, NoPlan, Refused }`. When a `TASK` turn produces zero valid tool calls, Sphinx returns a structured refusal enumerating the live `sutra::ToolRegistry` tools (`"I don't have a tool to <request>. My available tools are: ..."`).
   - **BUG B — Fibonacci Template Hijacking Generic C++ Requests (`RESOLVED`)**: Replaced `has_fib_or_cpp` with `is_fibonacci_benchmark_request(text)` matching only `"fibonacci"`, `"fib.cpp"`, or `"task_code.cpp"`. Generic C++ coding prompts route to `write_file` (default target `main.cpp`, `> 158` bytes) and standalone compile requests route to `compile_check`.
   - **BUG C — Narrow Read-Intent Keyword Set (`RESOLVED`)**: Expanded read-intent detection to the 21-entry `kReadIntentKeywords` table (`"audit"`, `"what does it do"`, `"explain the code"`, `"inspect"`, etc.), enforced the strict §3.3 plan-selection ordering so read-intent precedes write-intent, and updated the `read_file` summarizer branch to inject actual file contents and byte counts on non-truncated files.
   - **BUG D — CHAT False Confidence & Verification Routing (`RESOLVED`)**: Appended `kChatGroundingClause` to `build_chat_system_prompt`, included the last `N = 2` user/assistant turn pairs in `CHAT` `msgs`, and added stateful verification routing (`kVerifyKeywords` + `last_tool_invoked` in `TurnRouter::classify` and `SphinxSession::Impl`) so verification questions immediately following a tool turn re-read the target file on the `TASK` path.
13. **Secondary Operational Notes (Cold-Start Page Cache & Silent Calibration Window)**:
   - **Cold-Cache Model Startup Latency**: After OS reboot or kernel page-cache eviction, loading `Qwen2.5-1.5B-Instruct-Q4_K_M.gguf` (`986 MB`) and `Qwen3-30B-A3B-Q4_K_M.gguf` (`18.56 GB`) from disk can take `~4.17 s` (router) and `~62.74 s` (big model) versus `~0.63 s` and `~15.3 s` when warm in the Linux page cache. This is disk I/O bound on cold page cache rather than a code regression.
   - **`mic_rms=0.000` at Calibration**: If the ALSA capture ring delivers digital silence during the startup noise-floor calibration window (e.g., when a hardware mute switch is active or before PipeWire routes the source), `vad_threshold` falls back to the `0.022` default rather than a measured ambient floor. Harmless when typing; tracked for a follow-up calibration retry.
